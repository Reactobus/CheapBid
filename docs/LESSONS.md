# CheapBids — журнал ошибок и самообучение

Единый, версионируемый (под git) источник для:

1. **Чеклиста «перед готово»** — правила, выведенные из реальных факапов.
2. **Реестра ошибок** — что сломалось, почему, как починено, какое правило предотвращает повтор.

> Persistent-память (`.claude/.../memory`) для регистрации ошибок **не используется** — только этот
> файл. Он в репозитории, виден человеку, воркерам и в diff'ах, откатывается вместе с кодом.

Протокол самообучения описан в `CLAUDE.md` → раздел «Самообучение и ошибки».

## ✅ Чеклист «перед тем, как сказать ГОТОВО»

Пройти **целиком** перед любым заявлением, что правка готова/работает/протестирована:

- [ ] **Тесты зелёные** — `node tests/run.js`.
- [ ] **Покрыт путь игрока** — тест гоняет именно тот путь (scan / my bids / кнопка / хоткей /
      дабл-клик), который реально жмёт игрок, а не соседний. Симметричный код → симметричные тесты.
- [ ] **Задеплоено** — скопировал `CheapBids/{CheapBids.lua,CheapBids.toc,Bindings.xml}` в игровую
      папку `...\_anniversary_\Interface\AddOns\CheapBids\`.
- [ ] **Деплой проверен** — `grep` по строке из новой правки в **игровой** копии даёт `> 0`.
- [ ] **Сказал игроку `/reload`** (или перезайти).
- [ ] **Новый аддон/папка → полный рестарт игры, НЕ `/reload`.** Если правка добавляет *новую
      папку аддона* (напр. модуль-плагин), `/reload` её **не подхватит** — список аддонов строится
      только при старте клиента / на экране выбора персонажа. Правка существующих файлов уже
      загруженного аддона — `/reload` ок; новая папка — сказать игроку **выйти в выбор персонажа
      или перезапустить игру** и проверить галку в списке аддонов (см. ERR-0004).
- [ ] **Денежная/ставочная правка** — отдельно убедился, что лишнее золото не списывается
      (проверка порога/подтверждения покрыта тестом на конкретной сумме).
- [ ] **Не переприсваиваю глобальные таблицы Blizzard** (`StaticPopupDialogs`, `UISpecialFrames`,
      `SlashCmdList` и т.п.) — пишу **только в ключ** (`T["MY_KEY"] = {...}`). Запись в саму
      переменную (`T = T or {}`) заражает (taint) глобаль → секурные диалоги Blizzard падают
      «forbidden function ... from a tainted execution path» (см. ERR-0003).

Одна команда на деплой + проверку:
```bash
src="CheapBid/CheapBids"; dst="/c/Program Files (x86)/World of Warcraft/_anniversary_/Interface/AddOns/CheapBids"
cp -f "$src"/CheapBids.lua "$src"/CheapBids.toc "$src"/Bindings.xml "$dst"/
grep -c "<строка из моей новой правки>" "$dst/CheapBids.lua"   # должно быть > 0
```

## 📒 Реестр ошибок

Формат записи: `ERR-NNNN`, дата, симптом (что увидел игрок), корень, починка, правило, статус.

### ERR-0001 — ставка >5g ушла без подтверждения (списано 7g)
- **Дата:** 2026-06-20
- **Симптом:** игрок нажал `bid` по 7g-лоту в *scan auc* — окна подтверждения не было, золото списалось.
- **Корень:** confirm-код был написан и оттестирован, но **не скопирован** в игровую папку. В игре
  работала старая сборка без подтверждения. Логика была верная — не доехала до игры.
- **Починка:** деплой новой версии + `grep`-проверка наличия `BID_CONFIRM_COPPER` в игровой копии.
- **Правило:** чеклист → «Задеплоено» + «Деплой проверен». «Тесты прошли» ≠ «готово».
- **Статус:** закрыто.

### ERR-0002 — заявил «оттестировано», хотя путь игрока был не покрыт
- **Дата:** 2026-06-20
- **Симптом:** confirm добавлен и в scan (`BidItem`), и в my bids (`RebidBidder`), но тест гонял
  только my bids. Баг у игрока был на scan-пути — тест его поймать не мог.
- **Корень:** в тест-хук (`CheapBidsTest.fn`) был выведен только `RebidBidder`, не `BidItem`.
- **Починка:** вывел `BidItem`/`CommitScanBid` в хук; `ReadFilter` ранний выход без UI (для headless);
  добавил scan-тесты на 7g и на дешёвую ставку (48/48).
- **Правило:** чеклист → «Покрыт путь игрока».
- **Статус:** закрыто.

### ERR-0003 — заразили StaticPopupDialogs → блок «forbidden function (ReplaceEnchant)»
- **Дата:** 2026-06-28
- **Симптом:** игрок жал «Accept» на штатном диалоге замены энчанта (`REPLACE_ENCHANT`) — ошибка
  «AddOn CheapBids attempted to call a forbidden function (ReplaceEnchant()) from a tainted
  execution path». Аддон к энчантам отношения не имеет; ломался секурный диалог Blizzard.
- **Корень:** строка `StaticPopupDialogs = StaticPopupDialogs or {}` перед добавлением нашего
  `CHEAPBIDS_CONFIRM_BID`. Запись в **саму глобальную переменную** `StaticPopupDialogs` из
  небезопасного кода аддона заражает (taint) эту глобаль. После этого любой секурный попап
  Blizzard, читающий `StaticPopupDialogs[which]`, исполняется по заражённому пути, и его защищённый
  `OnAccept` (тут `ReplaceEnchant()`) блокируется клиентом. Логика подтверждения ставки была
  корректной — заражение давала ровно одна «защитная» строка `or {}`.
- **Починка:** убрал переприсваивание; пишем только в ключ `StaticPopupDialogs["CHEAPBIDS_CONFIRM_BID"]`.
  `StaticPopupDialogs` всегда существует на момент загрузки аддонов в 2.5.5, так что `or {}` не нужен.
- **Правило:** чеклист → «Не переприсваиваю глобальные таблицы Blizzard» (только запись в ключ).
- **Статус:** закрыто.

### ERR-0004 — «не показывает» новый модуль после `/reload` (ложная тревога → чуть не полез чинить код)
- **Дата:** 2026-07-09
- **Симптом:** добавили новый аддон-модуль `CheapBids_Disenchant` (тултип распыла, порт Enchantrix),
  скопировали в игровую папку, сказали игроку `/reload`. Тултип блок `Disenchants into:` **не
  появлялся**. Выглядело как баг хука тултипа под 2.5.6.
- **Корень:** **`/reload` (ReloadUI) не enumerľует только что созданную папку аддона.** Список
  аддонов формируется при запуске клиента и на экране выбора персонажа. Правка файлов *уже
  загруженного* аддона видна после `/reload`, а **новая папка** — только после полного рестарта
  игры / выхода в выбор персонажа. Код и деплой были корректны с самого начала; после рестарта
  игры блок подтянулся и считается верно (проверено: rare низкого ilvl → Small Glimmering Shard 100%).
- **Побочный вывод:** едва не начал «чинить» рабочий код (запустил аудит хука) по симптому, который
  на деле был операционным. Сначала подтвердить, что модуль реально В ПАМЯТИ, потом трогать код.
- **Починка:** ничего в коде; игрок перезапустил игру. `OnTooltipSetItem` + `HookScript` —
  корректный механизм на 2.5.6 (так же цепляются рабочие BagBrother/Bagnon, Postal, AtlasLoot).
- **Правило:** чеклист → «Новый аддон/папка → полный рестарт игры, НЕ `/reload`». Плюс: диагностика
  «не показывает» начинается с проверки загрузки (галка в списке аддонов / свой слэш вроде `/cbde`),
  а не с правки кода.
- **Статус:** закрыто.

### ERR-0005 — rarity-фильтр «не реагировал на выбор, потом сам заработал»
- **Дата:** 2026-07-09
- **Симптом:** на первой вкладке выбор редкости в дропдауне не фильтровал список сразу; через
  какое-то время фильтр «сам» начинал работать.
- **Корень:** качество лота берётся из `GetItemInfo` (снапшотное `it.qual` ненадёжно — см.
  cheapbids-getall-quality-unreliable), а `GetItemInfo` для незакэшированных предметов грузится
  **асинхронно**. На выборе редкости фильтр применялся, но у большинства лотов качество ещё не
  подгружено → они выпадали. Было лишь ОДНО пере-применение на 0.8с — на большом кэше не хватало;
  предметы докэшивались позже (при скролле/наведении) → «потом само». Плюс немедленное применение
  шло через `RequestApplyFilter` с троттлом 0.3с, и первый клик мог быть проглочен.
- **Починка:** rarity-клик применяет фильтр немедленно (`ApplyFilter`, минуя троттл — выбор редкости
  не спамится), и планирует серию пере-применений (0.4/1.0/2.0/4.0с), чтобы фильтр сходился сам по
  мере прогрева кэша `GetItemInfo`.
- **Правило:** любой фильтр/сортировка по данным из `GetItemInfo` (качество, тип, ilvl) обязан
  учитывать асинхронную догрузку: применять сразу + пере-применять несколько раз, пока кэш тёплый.
  Разовый таймер недостаточен.
- **Статус:** закрыто.
